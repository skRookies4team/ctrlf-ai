> 기존 PPT에서 부족한 "말로만 차별점"을 코드 기반 증거로 보강하는 자료

## 1. 검색 고도화: Query Expansion + RRF Fusion

### 왜 중요한가?
- **평가 결과 100% 달성의 핵심 기술**
- 짧거나 모호한 질문 → 검색 품질 저하 → Query Expansion으로 해결
- 단일 검색 결과의 한계 → RRF Fusion으로 상호 보완

### 1.1 Query Expansion (쿼리 확장)

**구현 파일**: `app/services/chat/query_rewriter.py`, `config/query_expansion_rules.yaml`

```
[동작 흐름]
사용자: "연차"
    ↓
[조건 체크] 2단어 이하 or 20자 이하? → 확장 필요
    ↓
[YAML 규칙 매칭] "연차" 키워드 발견
    ↓
[확장 결과] "연차 연차휴가 연간휴가 연가 유급휴가 휴가 사용 규정"
```

**핵심 설계**:
| 항목 | 값 | 이유 |
|------|-----|------|
| 최대 쿼리 길이 | 40자 | 이미 구체적인 질문은 확장 불필요 |
| 확장 키워드 수 | 최대 8개 | 검색 노이즈 방지 |
| 규칙 수 | 20개 핵심 키워드 | HR/보안/교육/징계 도메인 커버 |

**20개 키워드 분류**:
- HR (6개): 연차, 휴가, 출장, 급여, 퇴직, 복리후생
- 보안 (6개): 비밀번호, 보안, 보안사고, USB, 반출, 권한
- 교육 (3개): 교육, 필수교육, 법정교육
- 성희롱/괴롭힘 (3개): 성희롱, 괴롭힘, 신고
- 징계 (2개): 징계, 처분

---

### 1.2 RRF Fusion (Reciprocal Rank Fusion)

**구현 파일**: `app/services/search_merger.py` (라인 524-683)

```
[RRF 알고리즘]
score(문서) = Σ 1/(k + rank)    (k=60, 논문 권장값)

[실행 예시]
원문 쿼리 "연차" 검색 결과:
  1등: doc1 "연차휴가 규정"
  2등: doc2 "휴가 신청"
  3등: doc3 "복무규정"

확장 쿼리 "연차 연차휴가 휴가 규정" 검색 결과:
  1등: doc2 "휴가 신청"
  2등: doc4 "연차 잔여일수"
  3등: doc1 "연차휴가 규정"

RRF 점수 계산:
  doc1: 1/(60+1) + 1/(60+3) = 0.0316 ← 양쪽 등장
  doc2: 1/(60+2) + 1/(60+1) = 0.0325 ← 양쪽 등장 (최고점)
  doc3: 1/(60+3) = 0.0159
  doc4: 1/(60+2) = 0.0161

최종 순위: doc2 > doc1 > doc4 > doc3
→ 양쪽에 나타난 문서가 상위로 승격
```

**차별점**:
| 일반 RAG | 우리 시스템 |
|----------|-----------|
| 단일 쿼리 검색 | 원문 + 확장 쿼리 병렬 검색 |
| Top-K 그대로 반환 | RRF로 교차 검증된 결과 반환 |
| 짧은 쿼리 = 낮은 품질 | 짧은 쿼리 = 자동 확장 → 동등 품질 |

## 2. 환각 방지: 4계층 방어 시스템

### 왜 중요한가?
- "출처 제공"만으로는 환각 방지 불충분
- **없는 조항 인용, 근거 없는 통계 주장** = 치명적 신뢰도 하락
- 우리는 **환각 생성 자체를 구조적으로 차단**

### 2.1 4계층 방어 아키텍처

```
[Layer 1] Quality Gate (RAG 품질 판정)
          L2 거리 > 1.6 → LLM 호출 자체 차단
              ↓
[Layer 2] Citation Validation (조항 인용 검증)
          RAG에 없는 "제N조" 인용 → 답변 차단
              ↓
[Layer 3] Statistical Claim Block (통계 주장 차단)
          근거 없는 "TOP 5", "45%" → 답변 차단
              ↓
[Layer 4] Soft Guardrail (조건부 표현 강제)
          RAG 0건 → "확정 표현 금지" 지시
```

---

### 2.2 Layer 1: Quality Gate (L2 거리 기반)

**구현 파일**: `app/services/chat/quality_gate.py`

| L2 거리 | 등급 | 동작 | 의미 |
|--------|------|------|------|
| ≤ 1.4 | OK | 정상 진행 | 관련 문서 발견 |
| 1.4~1.6 | LOW | 경고 포함 | 관련도 낮음 |
| > 1.6 | **INSUFFICIENT** | **LLM 호출 스킵** | 관련 문서 없음 |

**핵심**: L2 > 1.6이면 LLM을 호출하지 않음 → **환각 원천 차단**

```python
# 실제 코드 (quality_gate.py:188-195)
if min_dist > reject_th:
    return QualityGateDecision(
        grade=QualityGrade.INSUFFICIENT,
        action=QualityAction.REJECT,  # LLM 호출 안 함
        clarify_message="죄송합니다. 질문에 대한 충분한 근거를 찾지 못했습니다."
    )
```

---

### 2.3 Layer 2: Citation Validation (조항 인용 검증)

**구현 파일**: `app/services/answer_guard_service.py` (라인 862-979)

```
[검증 로직]
LLM 답변: "제5조 제2항에 따르면 연차는 15일입니다"
              ↓
[Step 1] 답변에서 조항 패턴 추출: "제5조", "제2항"
              ↓
[Step 2] RAG sources에서 해당 조항 존재 여부 확인
              ↓
[Step 3] 없으면 → 답변 차단 + 안전 템플릿 반환
```

**조항 패턴 정규식**:
```python
r"(제\s*\d+\s*조|제\s*\d+\s*항|제\s*\d+\s*호|별표|부칙|시행령)"
```

**차단 시 응답**:
> "죄송합니다. 요청하신 내용에 대한 정확한 근거 문서를 확인하지 못했습니다.
> 정확한 조항 및 규정 정보는 담당 부서에 직접 문의해 주시기 바랍니다."

---

### 2.4 Layer 3: Statistical Claim Block (통계 주장 차단)

**구현 파일**: `app/services/answer_guard_service.py` (라인 124-186)

**차단 패턴**:
```python
STATISTICAL_CLAIM_PATTERNS = [
    r"TOP\s*\d+",        # "TOP 5"
    r"가장\s*많이",       # "가장 많이"
    r"\d+\s*위",         # "1위"
    r"약?\s*\d+\s*%",    # "45%", "약 45%"
    r"대부분의\s*경우",   # "대부분의 경우"
    r"통계에\s*따르면",   # "통계에 따르면"
]
```

**동작**: RAG sources 없이 위 패턴 감지 → **즉시 차단**

---

### 2.5 Layer 4: Soft Guardrail (조건부 표현 강제)

**구현 파일**: `app/services/answer_guard_service.py` (라인 563-590)

RAG 0건일 때 LLM 시스템 프롬프트에 추가:

```
[중요 지침 - 회사 기준 확정 표현 금지]

【금지 표현】
• '회사 규정상', '사규에 따르면', '정책에 따라'
• '의무적으로', '반드시', '무조건'
• 제N조, 제N항 등 구체적 조항 번호

【허용 표현】
• '일반적으로는 ~로 운영되는 경우가 많습니다'
• '회사마다 다를 수 있습니다'
```

**사용자에게 표시**:
> ⚠️ **현재 승인된 사내 문서에서 관련 근거를 찾지 못했습니다.**
> 아래 답변은 일반적인 지식을 바탕으로 한 참고 정보입니다.

## 3. 보안: PII 3단계 + Fail-Closed

### 왜 중요한가?
- 개인정보 유출 = 법적 책임 + 신뢰도 붕괴
- 단순 마스킹으로는 불충분 (입력만? 출력만? 로그는?)
- **장애 시에도 개인정보 보호 유지** = Fail-Closed

### 3.1 PII 3단계 마스킹 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│                    PII 3단계 보호                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [1단계: INPUT]        [2단계: OUTPUT]      [3단계: LOG]    │
│  사용자 입력 마스킹     LLM 응답 마스킹       로그 저장 마스킹 │
│                                                             │
│  "김철수 010-1234"     "홍길동님의 연차"     ES 저장 전      │
│       ↓                     ↓                    ↓          │
│  "[NAME] [PHONE]"      "[NAME]님의 연차"    마스킹된 Q&A    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**구현 위치**:
| 단계 | 파일 | 라인 |
|------|------|------|
| INPUT | `chat_service.py` | 631-680 |
| OUTPUT | `chat_service.py` | 1632-1681 |
| LOG | `ai_log_service.py` | 134-143 |

---

### 3.2 Fail-Closed 메커니즘

**핵심 원칙**: PII 마스킹 서비스 장애 시 → **원문 전송 금지**

```
[일반 시스템]                    [우리 시스템 - Fail-Closed]
PII 서비스 장애                  PII 서비스 장애
      ↓                                ↓
원문 그대로 전송 ❌               안전 fallback 메시지 반환 ✓
개인정보 유출 위험                "보안 검사 중 문제가 발생했습니다.
                                  잠시 후 다시 시도해 주세요."
```

**실제 코드** (`chat_service.py:651-680`):
```python
except PiiDetectorUnavailableError as e:
    # A7: PII 검출 실패 시 Fail-Closed
    logger.error(f"PII detector unavailable: {e.reason}")

    emit_security_event_once(
        block_type="PII_BLOCK",
        rule_id="PII_DETECTOR_UNAVAILABLE_INPUT",
    )

    # 원문이 아닌 안전한 fallback 반환
    return self._create_fallback_response(
        PII_DETECTOR_UNAVAILABLE_MESSAGE
    )
```

**장애 유형별 처리**:
- HTTP 4xx/5xx → Fail-Closed
- 타임아웃 (10초) → Fail-Closed
- 네트워크 에러 → Fail-Closed
- JSON 파싱 에러 → Fail-Closed

---

### 3.3 Privacy Query Gate (명단 요청 차단)

**구현 파일**: `app/services/privacy_query_gate.py`

**차단 조건**: 3개 요소 조합 감지

```
[조합 규칙]
대상(타인)     +    명단화 행위    +    민감 속성
"직원", "팀원"      "리스트", "뽑아"     "교육", "점수"
   (+2점)             (+3점)              (+3점)
                         ↓
                   총점 ≥ 6 → 차단
```

**예시**:
| 질문 | 판정 | 이유 |
|------|------|------|
| "교육 미이수 직원 명단 뽑아줘" | ❌ 차단 | 타인+명단+교육 |
| "내 교육 현황 알려줘" | ✅ 허용 | 1인칭 = 개인화 조회 |

## 5. PPT 슬라이드 요약
