# 슬라이드 1: 검색 고도화

## 제목
**Query Expansion + RRF Fusion으로 검색 정확도 100% 달성**

## 서브타이틀
짧은 질문도 놓치지 않는 지능형 검색 파이프라인

---

## 슬라이드 본문

### 좌측: 문제 상황
```
기존 RAG의 한계

사용자: "연차"
    ↓
단일 키워드 검색
    ↓
관련 문서 누락 ❌
정확도 36%
```

### 우측: 우리의 해결책
```
Query Expansion + RRF Fusion

사용자: "연차"
    ↓
[Query Expansion]
"연차 연차휴가 연간휴가 연가 유급휴가 휴가 규정"
    ↓
[병렬 검색]
원문 쿼리 검색 → 결과 A
확장 쿼리 검색 → 결과 B
    ↓
[RRF Fusion]
양쪽에 등장한 문서 = 높은 신뢰도
    ↓
교차 검증된 Top-K ✓
정확도 100%
```

### 하단: 핵심 수치

| 항목 | 값 |
|------|-----|
| 확장 키워드 | 20개 (HR/보안/교육/징계) |
| RRF k값 | 60 (논문 권장) |
| 정확도 개선 | 36% → **100%** |

---

## 발표자 노트
- "연차"처럼 짧은 질문은 기존 RAG에서 검색 품질이 낮습니다
- Query Expansion으로 "연차휴가, 연간휴가, 유급휴가" 등 동의어를 자동 추가합니다
- 원문 쿼리와 확장 쿼리를 병렬로 검색한 후, RRF 알고리즘으로 양쪽에 등장한 문서에 가중치를 부여합니다
- 이 방식으로 정확도를 36%에서 100%로 개선했습니다

# 슬라이드 2: 환각 방지 (1/2)

## 제목
**4계층 방어 시스템으로 환각 구조적 차단**

## 서브타이틀
"출처 제공"을 넘어, 환각 생성 자체를 막는 아키텍처

---

## 슬라이드 본문

### 전체 흐름도 (세로 배치)

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  사용자 질문                                         │
│      ↓                                              │
│  ┌─────────────────────────────────────────────┐   │
│  │ Layer 1: Quality Gate                        │   │
│  │ L2 거리 > 1.6 → LLM 호출 자체 차단            │   │
│  └─────────────────────────────────────────────┘   │
│      ↓ (통과)                                       │
│  ┌─────────────────────────────────────────────┐   │
│  │ Layer 2: Citation Validation                 │   │
│  │ RAG에 없는 "제N조" 인용 → 답변 차단           │   │
│  └─────────────────────────────────────────────┘   │
│      ↓ (통과)                                       │
│  ┌─────────────────────────────────────────────┐   │
│  │ Layer 3: Statistical Claim Block             │   │
│  │ 근거 없는 "TOP 5", "45%" → 답변 차단          │   │
│  └─────────────────────────────────────────────┘   │
│      ↓ (통과)                                       │
│  ┌─────────────────────────────────────────────┐   │
│  │ Layer 4: Soft Guardrail                      │   │
│  │ RAG 0건 → "확정 표현 금지" 지시               │   │
│  └─────────────────────────────────────────────┘   │
│      ↓                                              │
│  안전한 응답 반환 ✓                                 │
│                                                     │
└─────────────────────────────────────────────────────┘
```

---

## 발표자 노트
- 일반적인 RAG 시스템은 "출처 표시"로 신뢰성을 확보하지만, 이것만으로는 환각을 막을 수 없습니다
- 우리 시스템은 4계층으로 환각을 구조적으로 차단합니다
- Layer 1: 검색 결과의 L2 거리가 1.6을 초과하면 LLM을 호출하지 않습니다
- Layer 2: LLM이 "제5조"를 인용했는데 RAG에 없으면 차단합니다
- Layer 3: "TOP 5", "45%" 같은 통계 주장은 근거 없이 생성 불가합니다
- Layer 4: 근거가 없으면 "일반적으로~" 같은 조건부 표현만 허용합니다

# 슬라이드 3: 환각 방지 (2/2)

## 제목
**환각 방지 실제 동작 예시**

## 서브타이틀
각 계층별 차단 시나리오

---

## 슬라이드 본문

### Layer 1: Quality Gate

```
질문: "비밀번호 변경 주기"
    ↓
RAG 검색 결과: L2 거리 = 1.8 (> 1.6)
    ↓
판정: INSUFFICIENT
    ↓
응답: "질문에 대한 충분한 근거를 찾지 못했습니다.
      더 구체적으로 질문해 주시겠어요?"

→ LLM 호출 없이 안전 응답 반환
```

### Layer 2: Citation Validation

```
LLM 생성 답변: "제99조 제5항에 따르면..."
    ↓
RAG sources 확인: "제99조" 없음
    ↓
판정: HALLUCINATION DETECTED
    ↓
응답: "정확한 조항 정보는 담당 부서에 문의해 주세요."

→ 없는 조항 인용 원천 차단
```

### Layer 3: Statistical Claim Block

```
LLM 생성 답변: "위반 사례 TOP 5는..."
    ↓
패턴 감지: "TOP \d+" 매칭
    ↓
RAG sources: 해당 통계 없음
    ↓
응답: "통계 정보는 담당 부서에 문의해 주세요."

→ 근거 없는 수치 생성 차단
```

---

## 발표자 노트
- Layer 1: L2 거리가 1.6을 초과하면 "관련 문서가 없다"고 판단하고 LLM을 호출하지 않습니다. 이것이 가장 강력한 환각 방지입니다.
- Layer 2: LLM이 "제99조"를 인용했는데 RAG에 없으면 즉시 차단합니다. 실제로 없는 조항을 만들어내는 것을 막습니다.
- Layer 3: "TOP 5", "45%" 같은 통계 패턴을 정규식으로 감지합니다. 근거 없이 수치를 생성하면 차단합니다.

# 슬라이드 4: PII 3단계 보안

## 제목
**3단계 PII 마스킹 + Fail-Closed 아키텍처**

## 서브타이틀
입력부터 로그까지, 장애 상황에서도 개인정보 보호

---

## 슬라이드 본문

### 상단: 3단계 마스킹 흐름

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   [1단계: INPUT]       [2단계: OUTPUT]       [3단계: LOG]       │
│                                                                 │
│   사용자 입력           LLM 응답              로그 저장          │
│   "김철수 010-1234"    "홍길동님 연차"       Elasticsearch      │
│         ↓                   ↓                     ↓             │
│   "[NAME] [PHONE]"     "[NAME]님 연차"       마스킹된 Q&A       │
│                                                                 │
│   ✓ 마스킹 후 처리      ✓ 마스킹 후 반환      ✓ 원본 미저장     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 하단: Fail-Closed 메커니즘

```
┌─────────────────────────┐    ┌─────────────────────────┐
│    일반 시스템           │    │    우리 시스템           │
├─────────────────────────┤    ├─────────────────────────┤
│                         │    │                         │
│  PII 서비스 장애         │    │  PII 서비스 장애         │
│         ↓               │    │         ↓               │
│  원문 그대로 전송 ❌     │    │  Fail-Closed 발동       │
│         ↓               │    │         ↓               │
│  개인정보 유출 위험      │    │  안전 메시지 반환 ✓     │
│                         │    │  "보안 검사 중 문제가   │
│                         │    │   발생했습니다"         │
│                         │    │         ↓               │
│                         │    │  개인정보 보호 유지     │
│                         │    │                         │
└─────────────────────────┘    └─────────────────────────┘
```

### 우측 하단: Privacy Query Gate

```
명단 요청 자동 감지/차단

"교육 미이수 직원 명단 뽑아줘"
→ 타인 + 명단화 + 민감속성 = 차단 ❌

"내 교육 현황 알려줘"
→ 1인칭 = 개인화 조회 = 허용 ✓
```

---

## 발표자 노트
- 개인정보 보호는 입력 단계만으로는 불충분합니다. LLM이 응답에서 개인정보를 생성할 수 있고, 로그에 남을 수 있습니다.
- 우리는 INPUT, OUTPUT, LOG 3단계 전 구간에서 마스킹합니다.
- 가장 중요한 것은 Fail-Closed입니다. 마스킹 서비스가 장애나면 일반 시스템은 원문을 그대로 보내지만, 우리는 안전 메시지만 반환합니다.
- Privacy Query Gate로 "직원 명단 뽑아줘" 같은 개인정보성 요청도 자동 차단합니다.

# 슬라이드 5: 성능 검증 결과

## 제목
**정량적 품질 검증 체계와 결과**

## 서브타이틀
575개 배치 테스트 + LLM Judge + Golden 회귀 테스트

---

## 슬라이드 본문

### 좌측: 핵심 성과 지표

```
┌─────────────────────────────────────┐
│                                     │
│   정상 응답률                        │
│   ┌─────────────────────────────┐   │
│   │  36%  ━━━━━━━━━▶  100%     │   │
│   │       (+178% 개선)          │   │
│   └─────────────────────────────┘   │
│                                     │
│   평균 L2 거리 (검색 품질)           │
│   ┌─────────────────────────────┐   │
│   │  1.8+ ━━━━━━━━━▶  1.2~1.4  │   │
│   │       (-33% 개선)           │   │
│   └─────────────────────────────┘   │
│                                     │
│   환각 발생률                        │
│   ┌─────────────────────────────┐   │
│   │  측정불가 ━━━━━▶  0%        │   │
│   │       (구조적 차단)          │   │
│   └─────────────────────────────┘   │
│                                     │
└─────────────────────────────────────┘
```

### 우측: 평가 체계

```
┌─────────────────────────────────────┐
│  3단계 평가 파이프라인               │
├─────────────────────────────────────┤
│                                     │
│  [1] 배치 테스트                     │
│      • 575개 질문 자동 처리          │
│      • 응답 시간, 토큰, 에러 추적    │
│                                     │
│  [2] LLM Judge (GPT-4o)             │
│      • 정확성 (1-5점)               │
│      • 완전성 (1-5점)               │
│      • 관련성 (1-5점)               │
│      • 환각 여부 (Y/N)              │
│                                     │
│  [3] Golden 회귀 테스트              │
│      • 25개 핵심 쿼리               │
│      • 품질 저하 시 자동 알림        │
│                                     │
└─────────────────────────────────────┘
```

### 하단: Quality Gate 임계값

| L2 거리 | 등급 | 동작 |
|--------|------|------|
| ≤ 1.4 | OK | 정상 RAG 답변 |
| 1.4 ~ 1.6 | LOW | 경고 포함 답변 |
| > 1.6 | INSUFFICIENT | **LLM 호출 차단** |

---

## 발표자 노트
- 정상 응답률이 36%에서 100%로 개선되었습니다. Query Expansion과 RRF Fusion의 효과입니다.
- L2 거리는 검색 품질을 나타내는 지표로, 낮을수록 좋습니다. 1.8+에서 1.2~1.4로 33% 개선되었습니다.
- 환각 발생률은 구조적으로 0%입니다. L2 > 1.6이면 LLM을 호출하지 않기 때문입니다.
- 평가는 575개 질문 배치 테스트, GPT-4o를 Judge로 한 자동 평가, 25개 Golden 쿼리 회귀 테스트로 구성됩니다.

# 슬라이드 6: 기술 차별점 요약

## 제목
**Ctrl+F AI 핵심 기술 차별점**

## 서브타이틀
일반 RAG 시스템과의 비교

---

## 슬라이드 본문

### 비교표

| 영역 | 일반 RAG | Ctrl+F AI |
|------|----------|-----------|
| **검색** | 단일 쿼리 | Query Expansion + RRF Fusion |
| **환각 방지** | 출처 표시 | 4계층 구조적 차단 |
| **품질 판정** | 없음 | L2 거리 기반 Quality Gate |
| **PII 보호** | 입력 마스킹 | 3단계 + Fail-Closed |
| **정확도** | ~36% | **100%** |

### 핵심 메시지 (크게)

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   "환각은 출처 표시로 막는 게 아니라,                    │
│    생성 자체를 구조적으로 차단해야 합니다"               │
│                                                         │
│   "개인정보는 장애 상황에서도 보호되어야 합니다"         │
│                                                         │
│   "짧은 질문도 놓치지 않는 검색이 진짜 RAG입니다"        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

---

## 발표자 노트
- 일반 RAG는 검색 결과를 그대로 LLM에 전달하고 출처를 표시합니다. 하지만 LLM은 여전히 없는 내용을 만들어낼 수 있습니다.
- Ctrl+F AI는 검색 품질이 낮으면 LLM을 호출하지 않고, 조항 인용과 통계 주장을 검증하며, 근거가 없으면 확정 표현을 금지합니다.
- PII 보호도 입력 단계만 하는 것이 아니라 출력, 로그까지 3단계로 보호하고, 장애 시에도 Fail-Closed로 원문을 전송하지 않습니다.
- 이러한 구조적 접근이 정확도 100%, 환각률 0%를 달성한 비결입니다.
