# AI 채팅 서비스 성능 개선 보고서 - Phase 51

## 1. 개요

### 1.1 프로젝트 배경
본 보고서는 CTRL+F AI 채팅 서비스의 **개인화 라우팅 개선 및 Milvus 쿼리 버그 수정** 작업을 기술합니다. Phase 50에서 LowRelevanceGate가 개선된 후, 개인화 질문(Q1~Q20)에 대한 라우팅 정확도를 향상시키고, Milvus 한글 조건 조합 쿼리 버그를 수정하였습니다.

### 1.2 개선 목표
| 목표 | 상세 |
|------|------|
| 개인화 라우팅 키워드 확장 | EDU_STATUS, EDU_RESUME, HR_PERSONAL, QUIZ 키워드 대폭 확장 |
| Personalization Mapper 추가 | SubIntentId → Q1-Q20 변환 매핑 레이어 신규 구현 |
| Sub-Intent Resolver 개선 | pending_sub_intent_id 추가, 키워드 매핑 강화 |
| Milvus 한글 쿼리 버그 수정 | `==` 연산자 → `in` 연산자로 변경하여 한글 조건 조합 버그 해결 |
| OpenAI API 지원 추가 | 임베딩용 OpenAI API 선택적 사용 지원 |

## 2. 문제 분석

### 2.1 발견된 문제

Phase 50 이후 운영 테스트에서 다음과 같은 문제가 발견되었습니다:

| 쿼리 | 증상 | 원인 |
|------|------|------|
| "보던 교육 이어보기" | 개인화 라우팅 실패 | EDU_RESUME 키워드 부재 |
| "내 퀴즈 점수 어때?" | 개인화 라우팅 실패 | QUIZ_SCORE 키워드 부재 |
| "안 푼 퀴즈 있어?" | 개인화 라우팅 실패 | QUIZ_PENDING 키워드 부재 |
| "이번 주 할 일 뭐야?" | Q9로 라우팅 안 됨 | EDU_STATUS 세분화 누락 |
| Milvus 한글 조건 조합 | 검색 결과 0건 | `==` 연산자 한글 버그 |

#### 3.2.2 EDU_STATUS_CHECK 세분화

```python
# EDU_STATUS_KEYWORDS: Q별 키워드 매핑
EDU_STATUS_KEYWORDS: dict[str, list[str]] = {
    "Q1": ["미이수", "안 들은", "안들은", "필수 미이수", "안한 교육"],
    "Q3": ["데드라인", "마감", "이번 달", "이번달", "이달", "곧 마감"],
    "Q9": ["이번 주", "이번주", "할 일", "해야 할", "해야할", "금주"],
}

def _classify_edu_status(query: str) -> str:
    """EDU_STATUS_CHECK를 query 키워드로 Q1/Q2/Q3/Q9 중 하나로 세분화"""
    q_lower = query.lower()

    # Q1: 미이수 필수 교육
    for keyword in EDU_STATUS_KEYWORDS["Q1"]:
        if keyword in q_lower:
            return "Q1"

    # Q3: 이번 달 데드라인
    for keyword in EDU_STATUS_KEYWORDS["Q3"]:
        if keyword in q_lower:
            return "Q3"

    # Q9: 이번 주 할 일
    for keyword in EDU_STATUS_KEYWORDS["Q9"]:
        if keyword in q_lower:
            return "Q9"

    # 기본: Q2 (수료현황/진도)
    return "Q2"
```

#### 3.2.4 기간(Period) 파싱

```python
PERIOD_KEYWORDS: dict[str, str] = {
    # this-week
    "이번 주": "this-week", "이번주": "this-week", "금주": "this-week",
    # this-month
    "이번 달": "this-month", "이번달": "this-month", "이달": "this-month",
    # 3m (3개월)
    "3개월": "3m", "최근 3개월": "3m",
    # this-year
    "올해": "this-year", "금년": "this-year",
}

def extract_period_from_query(query: str) -> Optional[str]:
    """사용자 쿼리에서 기간(period)을 추출"""
    q_lower = query.lower()
    for keyword, period in PERIOD_KEYWORDS.items():
        if keyword in q_lower:
            return period
    return None
```

```
Output: "Q11" (연차 조회)
```

### 3.4 Phase 51-4: Milvus 한글 조건 조합 쿼리 버그 수정

**파일**: `app/clients/milvus_client.py`

#### 3.4.1 `==` 연산자 → `in` 연산자로 변경

```python
# Before (버그 발생)
expr = f'doc_id == "{safe_doc_id}"'
if dataset_id:
    safe_dataset_id = escape_milvus_string(dataset_id)
    expr = f'{expr} && dataset_id == "{safe_dataset_id}"'

# After (버그 우회)
# 필터 표현식 구성 (in 연산자 사용 - 한글 && == 조합 버그 우회)
expr = f'doc_id in ["{safe_doc_id}"]'
if dataset_id:
    safe_dataset_id = escape_milvus_string(dataset_id)
    expr = f'{expr} && dataset_id in ["{safe_dataset_id}"]'
```

**근거**:
- Milvus에서 한글 문자열과 `==` 연산자를 `&&`로 조합할 때 파싱 오류 발생
- `in` 연산자는 단일 값 리스트로 사용해도 동일한 기능을 수행하며, 한글 버그 없음

**효과**:
```
Before: doc_id == "정보보안교육.pdf" && dataset_id == "사내규정" → 파싱 오류 → 결과 0건
After:  doc_id in ["정보보안교육.pdf"] && dataset_id in ["사내규정"] → 정상 검색
```

## 5. 기술적 인사이트

### 5.1 개인화 라우팅 아키텍처

```
┌─────────────────┐
│   User Query    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   RuleRouter    │  "보던 교육 이어보기"
│ (키워드 매칭)   │
└────────┬────────┘
         │ sub_intent_id = "EDU_RESUME_CHECK"
         ▼
┌─────────────────┐
│ Personalization │  query 분석
│    Mapper       │
└────────┬────────┘
         │ personalization_q = "Q4"
         ▼
┌─────────────────┐
│ Personalization │  facts 조회
│    Client       │
└────────┬────────┘
         │ facts (JSON)
         ▼
┌─────────────────┐
│    Answer       │  LLM 답변 생성
│   Generator     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ ChatResponse    │
└─────────────────┘
```

### 5.2 Milvus 쿼리 연산자 비교

```
[버그] == 연산자 + 한글 + &&
expr = 'field1 == "한글값" && field2 == "다른값"'
→ Milvus 내부 파서에서 한글 유니코드 처리 오류

[해결] in 연산자 + 한글 + &&
expr = 'field1 in ["한글값"] && field2 in ["다른값"]'
→ 정상 동작 (단일 값 리스트도 in 연산자로 처리 가능)
```

### 5.3 Sub-Intent Resolver 패턴

```
[Pattern] 치명 액션 vs 조회성 액션 분리

치명 액션 (CRITICAL_ACTION_SUB_INTENTS):
- QUIZ_START, QUIZ_SUBMIT, QUIZ_GENERATION
- 반드시 confirmation 필요
- pending_sub_intent_id로 다음 턴 연결

조회성 액션:
- HR_LEAVE_CHECK, EDU_STATUS_CHECK, QUIZ_SCORE_CHECK 등
- 바로 개인화 API 호출
- 즉시 응답 반환
```
