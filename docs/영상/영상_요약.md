## 1. 시스템 개요

### 🎯 **영상 생성 파이프라인**

CTRLF AI는 **2-Phase 비동기 영상 생성** 시스템을 운영합니다:

```
Phase 1: 스크립트 생성 (LLM 기반)
Phase 2: 영상 렌더링 (다중 방식 지원)
```

### 🔧 **렌더링 방식**

| 방식         | 설명                  | 특징                      |
| ------------ | --------------------- | ------------------------- |
| **FFmpeg**   | 내부 렌더링 엔진      | 기본 텍스트 + 오디오 영상 |
| **Heygen**   | 외부 AI 아바타 서비스 | 고품질 아바타 영상        |
| **Animated** | 시각적 효과 추가      | 이미지 + 애니메이션       |

### 📊 **데이터 모델**

**백엔드 EducationScript** 데이터만으로 모든 렌더링 방식 지원:

#### EducationScript 엔티티 구조

```
EducationScript (메인)
├── EducationScriptChapter (챕터들)
│   └── EducationScriptScene (씬들)
│       ├── narration (TTS 음성)
│       ├── caption (화면 자막)
│       ├── durationSec (씬 길이)
│       ├── purpose (씬 목적)
│       └── visual (시각적 설명)
```

#### 렌더링 데이터 매핑

| EducationScriptScene 필드 | AI 렌더링 용도              |
| ------------------------- | --------------------------- |
| `narration`               | TTS 음성 합성 + Heygen 입력 |
| `caption`                 | 화면 자막 텍스트            |
| `durationSec`             | 씬 길이 제어                |
| `purpose`                 | 씬 타입 분류                |
| `visual`                  | Animated 모드 시각적 계획   |

**EducationScript 데이터만으로 FFmpeg/Heygen/Animated 모두 지원 가능**

## 2. 주요 컴포넌트

### 📁 **핵심 파일들**

#### 백엔드 (Spring Boot)

- `VideoService.java`: 영상 작업 생성 및 관리
- `VideoController.java`: 영상 관련 API 엔드포인트
- `VideoAiClient.java`: AI 서버와의 통신 클라이언트

#### AI 서버 (FastAPI)

- `render_jobs.py`: 렌더링 작업 API
- `video_script_generation_service.py`: LLM 스크립트 생성
- `render_job_runner.py`: 렌더링 작업 오케스트레이터
- `video_renderer_real.py`: 실제 영상 렌더러 (7-Step)
- `heygen_client.py`: Heygen API 클라이언트

### 🔄 **주요 플로우**

```
사용자 요청 → 백엔드 → AI 서버 → 렌더링 → (S3 업로드: Presigned URL 발급 → PUT 업로드) → 콜백 → 완료
```

## 3. API 엔드포인트

### 🔗 **주요 API 목록**

#### 스크립트 관리 (백엔드)

- `GET /internal/scripts/{scriptId}/render-spec` - 렌더링용 스크립트 데이터 조회
- 기타 스크립트 CRUD API들 (EducationScript 기반)

#### 렌더링 작업

- `POST /internal/ai/render-jobs` - 백엔드 → AI 작업 생성
- `POST /ai/video/job/{jobId}/start` - 작업 시작
- `POST /ai/video/job/{jobId}/retry` - 작업 재시도

#### 상태 모니터링

- `WS /ws/videos/{video_id}/render-progress` - 실시간 진행률

#### 콜백

- `POST /internal/video/job/{jobId}/complete` - 렌더링 완료 알림 (AI → 백엔드, 내부 API)

#### 스토리지 업로드 (백엔드 Internal API, AI → 백엔드)

> AI 서버가 `STORAGE_PROVIDER=backend_presigned` 일 때 사용하는 업로드 방식입니다.  
> 내부적으로 infra-service의 presigned URL 발급 API를 호출해 `uploadUrl`을 받은 뒤, AI가 `PUT uploadUrl`로 업로드합니다.

- `POST /internal/storage/presign-put` - Presigned PUT URL 발급 (AI → 백엔드)
- `POST /internal/storage/complete` - 업로드 완료 알림 (AI → 백엔드)
- `POST /internal/storage/delete` - (옵션) 삭제 요청 (현재 no-op)

#### S3 Presigned 업로드 (infra-service)

- **Presigned Upload URL 발급**: `POST /infra/files/presign/upload`
  - **요청 Body**: `{"fileName":"<name>","contentType":"<mime>","type":"image|docs|video"}`
  - **응답 Body**: `{"uploadUrl":"https://...","fileUrl":"s3://bucket/key"}`
- **Presigned URL로 PUT 업로드(직접)**: `PUT {uploadUrl}` (헤더 `Content-Type` 포함)
- **서버 프록시 업로드(대안)**: `POST /infra/files/presign/upload/put?url={uploadUrl}` (multipart form-data로 `file`)

## 4. 테스트 플로우 (간략)

> 목표: **Seed 더미 데이터 → render-spec 확인 → AI 렌더링 실행 → 콜백 수신**까지 end-to-end 확인

### 4.1 Seed 데이터 준비 (education-service)

- **실행 조건**: `SeedDataRunner`가 동작하는 프로필로 기동 (예: `dev-seed` 또는 `local-seed`)
- **결과 기대값**:
  - `EducationVideo.status = SCRIPT_APPROVED`
  - `EducationVideo.scriptId` / `EducationVideo.sourceSetId` 세팅됨
  - `EducationScriptChapter` / `EducationScriptScene` 데이터 존재

### 4.2 render-spec 확인 (education-service → AI가 조회하는 스펙)

- `GET /internal/scripts/{scriptId}/render-spec`
  - **기대값**: scenes 배열이 비어있지 않음, narration/caption/duration 값 존재

### 4.3 AI 렌더링 실행 (education-service → AI)

- `POST /internal/ai/render-jobs`
  - **입력**: `jobId`, `videoId`, `scriptId` (+ `requestId` 권장)
- `POST /ai/video/job/{jobId}/start`
  - **기대값**: Job 상태가 `PROCESSING`으로 진행

### 4.4 진행률/완료 확인

- **진행률**: `WS /ws/videos/{video_id}/render-progress`
- **완료 콜백(백엔드 수신)**: `POST /internal/video/job/{jobId}/complete`
  - **기대값**: 완료 시 `videoUrl`(또는 fileUrl) 저장/반영
